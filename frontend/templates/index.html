Sub-reports

A sub-report is a second report that a row in this one opens. Drop its files here — its Oracle .xml, an existing .rdl, or its SQL — and this tool builds it the same way it built the main report.

Where the finished report will read its data. Oracle keeps the report’s SQL exactly as Oracle wrote it. SQL Server rewrites it into T-SQL (Microsoft’s version of SQL). Choose this before you convert — changing it later means converting again.

A shared data source is the saved database connection that already exists on your report server. Type its full path — or just its name, if it sits in the same folder as the report. Every file this tool makes points at it: the main report, its sub-reports and the burst pack. An uploaded report then connects on its own, so you never have to point it at the database by hand. This browser remembers what you type.

Most people can leave this blank. When a row in one report opens a second report, this tool always builds that as a web link that carries the row’s values with it. A web link keeps working after the report is exported to PDF — SSRS’s own built-in link does not survive an export to PDF, Word or Excel. Left blank, the report works out its own address while it runs (Globals!ReportServerUrl + Globals!ReportFolder). That needs no setup on SSRS 2016 or newer. Fill it in for older servers, or to send the links to a particular folder. Type your report server address up to the folder, for example http://host/ReportServer?/MyReports. Use the ReportServer address, not the /Reports portal one. The second report has to be on the server, in that folder, under its exact name. This browser remembers what you type.

These are the exact words the link shows on the cover page — both the “generate all” link and any “[field] is a hyperlink to…” line. Type the name a reader would recognise, for example Standard #10 Envelope, then convert or download again. The link then reads exactly that instead of the raw report name. Leave it blank and the link falls back to the report name. This tool cannot invent a friendly description for you, so if you want one, type it here. This browser remembers what you type.

Report images (seals / logos)

These are the picture slots this tool found in the report’s layout. Any picture stored inside the Oracle export loads by itself. To fill or replace a slot, upload a PNG, GIF or JPG: it goes into the .rdl file and appears in the preview straight away.

Convert many reports at once

Pick a whole folder of Oracle XML exports. Every report is converted and scored, and you get one Migration Assessment covering the set: how much hand-finishing each report needs, whether it will upload cleanly, and how much of the original came across.

    Turn an Oracle report into an SSRS report

    Drop the Oracle export — one .xml or .rdf file, or the whole folder that came with it — into the panel on the left. You get back an .rdl file you can upload to SSRS (SQL Server Reporting Services, Microsoft’s reporting server), plus a preview of the pages it will print.

    Start in Preview and RDL XML. Open Advanced views for the checks, an Oracle-beside-SSRS comparison, a test run of the report’s SQL, and the steps for going live.

    Generated RDL

    This is the report file this tool wrote for you — an RDL (Report Definition Language) file, the format SSRS reads. It is the thing you download and upload to the server. You do not have to read it; it is here so you can check anything you want to check. A very long file shows only its beginning here, but every download contains the whole file.

    Sub-Reports

    A sub-report is a second report that a row in the main report opens — the envelope for one permit, say, or the detail behind one line. Build one from whatever you have: its Oracle XML, an existing .rdl, or just its SQL (.sql, .docx or .txt). Drop the files onto a card below, or into the Sub-reports box in the panel on the left, then click Build & preview. You get a full report file and a preview, the same way you do for the main report.

    Oracle XML → RDL XML

    The Oracle file you dropped in is on the left; the SSRS file this tool wrote is on the right. Search both sides for a column or query name when you need to answer “where did this end up?” — for yourself, or for whoever asks how a number got onto the page.

    Validation

    Everything this tool checked before you deploy. Each finding says what will happen when the report runs, and what to do about it. Four words are used, most urgent first: BLOCKER — the file will not upload or open cleanly; fix this first. RED — it uploads, but something is likely to go wrong once the report runs. AMBER — worth reading; the report should still run. READY — nothing is standing in your way.

    Deploy Checklist

    The steps for putting this report on your server, in order. Steps marked Done for you are already handled inside the file you download — they are listed so you can see what was done. Steps marked You do this, Needs finishing or Take care need a person.
